Installation & Authentification

De zéro à opérationnel en moins de 2 minutes. Suivez ces étapes pour installer et configurer Gemini CLI.

▲

Installation globale

Installez Gemini CLI globalement via npm. C'est la méthode recommandée pour une utilisation régulière.

bash 
npm install -g @google/gemini-cli

# Vérifier l'installation
gemini --version

Prérequis : Node.js 18+ et npm. Sur macOS, vous pouvez aussi utiliser brew install node.

▲

Essayer sans installer

Utilisez npx pour exécuter Gemini CLI sans installation permanente. Parfait pour tester rapidement.

bash 
npx @google/gemini-cli

# Ou avec un prompt directement
npx @google/gemini-cli -p "Hello Gemini!"
🔑

Authentification Sécurisée

Ne laissez jamais traîner vos clés API en clair. Voici les meilleures méthodes pour s'authentifier via Google AI Studio.

Méthode 1 : Variables Sécurisées (Pro)

  1. Créez votre clé sur Google AI Studio
  2. Utilisez un gestionnaire comme 1Password CLI ou direnv pour l'injecter dynamiquement :
    bash 
    # Exemple avec 1Password CLI dans ~/.zshrc
export GEMINI_API_KEY=$(op read "op://Private/Gemini/credential")

# Ou classique : export direct
export GEMINI_API_KEY="votre_cle_api_ici"
  3. Rechargez votre shell : source ~/.zshrc

Méthode 2 : Fichier .env local

Créez un fichier .env dans ~/.gemini/ (global) ou ./.gemini/ (projet) :

env 
# ~/.gemini/.env
GEMINI_API_KEY="votre_cle_api_ici"
✓ Astuce Pro

Ajoutez toujours .gemini/ à votre .gitignore racine pour éviter de commiter vos configurations de projet et clés. Utilisez la méthode .env par projet pour gérer différents comptes API.

🎯

Premier lancement

Lancez Gemini CLI et commencez à interagir immédiatement :

bash 
# Mode interactif (REPL) - Conversation continue
gemini

# Mode non-interactif - Une seule réponse
gemini -p "Explique-moi le pattern MVC en 3 phrases"

# Mode interactif avec prompt initial
gemini -i "Aide-moi à refactorer ce projet"

# Piping - Envoyer du contenu via pipe
cat README.md | gemini -p "Résume ce fichier"

# Mode sandbox sécurisé (Docker/Podman requis)
gemini --sandbox -p "Analyse ces logs d'erreur"

▲ Flags en ligne de commande Avancé

Options disponibles au lancement de Gemini CLI.

Flag Description Exemple concret
-p <prompt> Exécute en mode non-interactif avec un prompt gemini -p "Liste les bugs du code"
-i <prompt> Démarre interactif avec un prompt initial gemini -i "Aide-moi à debug ce crash"
-m <modèle> Utilise un modèle spécifique gemini -m gemini-2.5-pro
-r <modèle> Spécifie le modèle pour les réponses gemini -r gemini-2.5-flash
--sandbox Exécute les outils dans un sandbox Docker/Podman gemini --sandbox -p "Test ce script"
--yolo Auto-approuve tous les appels d'outils gemini --yolo -p "Refactor tout"
--checkpointing Sauvegarde un snapshot avant modifications gemini --checkpointing
--json Force la sortie en JSON structuré (très utile en headless/CI) gemini --json -p "Liste les dépendances"
-d / --debug Active les logs de debug gemini -d -p "Test API call"

⚙ Configuration

Configuration & Personnalisation

Personnalisez Gemini CLI selon vos préférences et les besoins de chaque projet.

settings.json — Votre centre de contrôle

Le fichier settings.json est le cœur de la configuration. Il existe 3 niveaux de priorité :

Projet .gemini/settings.json
→
Utilisateur ~/.gemini/settings.json
→
Système /etc/gemini-cli/settings.json

Le fichier projet surcharge l'utilisateur, qui surcharge le système. Cela permet de configurer chaque projet différemment.

json 
{
  "theme": "GitHub",
  "autoAccept": false,
  "sandbox": "docker",
  "vimMode": true,
  "checkpointing": { "enabled": true },
  "fileFiltering": { "respectGitIgnore": true },
  "includeDirectories": ["../shared-lib"],
  "chatCompression": {
    "contextPercentageThreshold": 0.6
  }
}

GEMINI.md — Instructions Système intelligentes

Les fichiers GEMINI.md agissent comme un System Prompt hyper-contextuel. Ils se chargent hiérarchiquement :

  1. Global : ~/.gemini/GEMINI.md — Votre persona ("Réponds toujours en français, sois concis")
  2. Projet : ./GEMINI.md — Les conventions d'architecture de votre repo
  3. Sous-répertoire : instructions spécifiques par composant

Utilisez /init pour générer un GEMINI.md initial automatiquement.

markdown 
# Directives Projet

## Règles générales
- TypeScript strict obligatoire
- Ne propose pas de bibliothèques tierces non présentes dans le package.json
- **Thinking Process :** Pense toujours étape par étape avant d'écrire du code
- Tout le code Python doit suivre PEP 8
- Utiliser 2 espaces d'indentation pour le JS

## Documentation de référence
@./docs/architecture.pdf
@./docs/api-specs.md

## Imports modulaires
@./src/frontend/react-style-guide.md
@./src/backend/fastapi-conventions.md
💡 Idée

Utilisez @file.md pour modulariser vos instructions ! Séparez les conventions frontend, backend, tests, etc. dans des fichiers dédiés.

.geminiignore — Maîtriser le Contexte Géant

Même si Gemini gère jusqu'à 2 Millions de tokens, limiter le bruit augmente la précision et réduit les coûts. Créez un .geminiignore pour exclure les fichiers inutiles lors de l'utilisation de @./. Similaire à .gitignore.

gitignore 
# .geminiignore

MCP Servers — Étendre les capacités Avancé

Configurez des serveurs MCP (Model Context Protocol) pour ajouter des outils personnalisés. Utilisez gemini mcp add en CLI ou configurez directement dans settings.json :

json 
{
  "mcpServers": {
    "myPythonServer": {
      "command": "python",
      "args": ["-m", "my_mcp_server", "--port", "8080"],
      "cwd": "./mcp_tools/python",
      "env": { "DATABASE_URL": "$DB_URL_FROM_ENV" },
      "timeout": 15000,
      "trust": false,
      "includeTools": ["safe_tool_1", "safe_tool_2"],
      "excludeTools": ["dangerous_tool"]
    }
  }
}
💡 Transport

Stdio : command + args + cwd pour lancer un process local.
SSE : url pour un endpoint SSE (ex: http://localhost:8080/sse).
HTTP : httpUrl pour un endpoint HTTP streaming (ex: http://localhost:8080/mcp).

OptionDescription
envVariables d'environnement. Utilisez $VAR_NAME pour référencer le shell
headersHeaders HTTP pour les transports url/httpUrl
timeoutTimeout en ms (défaut: 10 min)
trustContourne toutes les confirmations d'outils pour ce serveur
includeToolsWhitelist des outils autorisés
excludeToolsBlacklist d'outils (priorité sur includeTools)

Exécution de Code (Code Interpreter)

bash

calcule le revenu total par mois avec pandas.
Affiche-moi le résultat final."

Checkpointing & Restore

Sauvegardez des snapshots de votre projet avant chaque modification. L'option checkpointing effectue un "commit silencieux" avant chaque exécution d'outil. Si le code généré casse tout, restaurez en 1 seconde.

bash 
# Activer le checkpointing
gemini --checkpointing

# Lister les checkpoints disponibles
/restore

# Restaurer un checkpoint spécifique
/restore checkpoint_20250520_143022
🤖

Mode Headless

Exécutez Gemini CLI sans interface interactive. Idéal pour l'automatisation, les pipelines CI/CD et les scripts batch.

bash 
# Mode headless pour automatisation
gemini -p "Génère les tests unitaires" --yolo

# Dans un script CI/CD
gemini -p "Review ce PR et signale les problèmes" \
  --sandbox 2>&1 | tee review.log

Model Routing & Steering Expérimental

Gemini CLI peut router intelligemment les requêtes vers différents modèles selon la complexité. Les tâches simples utilisent Flash (rapide), les tâches complexes utilisent Pro (puissant).

bash 
# Utiliser un modèle spécifique
gemini -m gemini-2.5-pro

# Flash pour les tâches rapides
gemini -m gemini-2.5-flash -p "Corrige cette typo"

# Gemini 3 Pro (si disponible)
# Via /settings > Preview Model

Git Worktrees Expérimental

Travaillez sur plusieurs branches simultanément. Gemini CLI peut créer et gérer des worktrees pour paralléliser vos développements sans conflits.

bash 
# Créer un worktree pour une feature

# Lancer Gemini CLI dans le worktree

💡 Conseils

Conseils d'Utilisation Pro

Optimisez votre workflow avec ces conseils éprouvés par la communauté.

💡 Chain of Thought (Pensée en étapes)

Forcez l'IA à analyser avant de coder. Ajoutez : "Analyse d'abord le problème étape par étape dans des balises <thinking> avant de fournir la solution en code." La qualité des réponses sur des bugs complexes sera décuplée.

💡 Few-Shot Prompting

Donnez des exemples. Si vous voulez un style de code précis, passez-lui un fichier exemple : "Voici comment j'écris mes tests @./exemple.test.js. Écris les tests pour @./nouveauFichier.js en suivant exactement le même pattern."

✓ Toujours utiliser checkpointing

Activez --checkpointing pour les tâches de modification de code. Cela vous permet de revenir en arrière si le résultat n'est pas satisfaisant. Combinez avec /restore pour un filet de sécurité complet.

✓ Organisez vos GEMINI.md

Un bon GEMINI.md fait toute la différence. Documentez vos conventions de code, l'architecture du projet, les dépendances clés et les pièges à éviter. Utilisez les imports @file.md pour rester organisé.

⚠ Attention au YOLO mode

--yolo auto-approuve tous les appels d'outils. C'est pratique mais risqué ! Ne l'utilisez que sur des projets que vous pouvez restaurer facilement. Toujours activer le checkpointing avec YOLO.

⚠ Limitez le contexte

Ne référencez pas tout un projet avec @./ si vous n'avez besoin que d'un fichier. Plus le contexte est grand, plus les réponses sont lentes et coûteuses en tokens. Soyez ciblé avec @.

Prompts : Mauvais vs Bons

✕ Trop vague (Hallucinations fréquentes)

  • "Refactor tout le projet"
  • "Corrige les bugs de l'API"
  • "Fais une interface de login stylée"
  • "Optimise cette fonction"
  • "Ajoute des tests"

✓ Contextuel et Directif (Exécution parfaite)

  • "Dans @./src/auth.ts, extrais la validation de mot de passe dans une fonction pure."
  • "L'endpoint POST /users renvoie 500 quand l'email existe déjà. Ajoute un try/catch et un code 409."
  • "À partir de @./maquette.png, crée un composant React avec TailwindCSS. Reste fidèle aux couleurs."
  • "Réduis la complexité cyclomatique de la méthode calculateTax dans @./billing.ts."
  • "Génère des tests Jest pour @./cart.ts en couvrant les edge cases : panier vide, quantité 0, prix négatif"

🎯 Workflow complet type

Voici un workflow réaliste pour utiliser Gemini CLI au quotidien sur un projet de développement :

  1. Initialisation du projet — Lancez /init pour générer un GEMINI.md adapté à votre projet. Personnalisez-le avec vos conventions.
  2. Configuration — Activez le checkpointing (--checkpointing) et configurez votre settings.json avec autoAccept: false pour garder le contrôle.
  3. Développement itératif — Décrivez vos besoins avec précision, référencez les fichiers avec @, et validez chaque modification proposée.
  4. Tests & Validation — Demandez à Gemini d'écrire les tests, exécutez-les avec !npm test, et itérez sur les échecs.
  5. Review & Documentation — Avant de commit, demandez une review complète et la mise à jour de la documentation.
  6. Sauvegarde — Utilisez /chat save pour garder une trace de vos sessions de travail.
